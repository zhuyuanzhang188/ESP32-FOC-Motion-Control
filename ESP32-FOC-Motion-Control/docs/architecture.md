# 软件架构

本项目采用单轴运动控制结构：**串口协议 → 运动任务管理 → 轨迹规划 → 电机控制**，同时并行完成状态监测和非阻塞数据发送。

```text
串口指令（B / C / N / P ...）
             │
             ▼
      SerialProtocol
             │
             ▼
      MotionController ◄──── TrajectoryPlanner
      （任务与接管）        （位置/速度/加速度求值）
             │
             ▼
         MotorControl
      （位置/速度参考、FOC）
             │
             ▼
     ESP32 + DengFOC + BLDC
             │
             └──── AS5600 / 电流反馈

    Diagnostics → Telemetry → 串口 CSV / VOFA
```

| 模块 | 职责 |
| --- | --- |
| `MotorControl` | 电机、驱动器、编码器、电流采样、SimpleFOC 初始化与闭环调用，速度前馈 |
| `TrajectoryPlanner` | 梯形与 S 曲线、受控停止及在线重规划轨迹数学 |
| `MotionController` | 任务状态、自动往返、接管、到位判断和运动编号 |
| `SerialProtocol` | 接收并检查串口参数，输出状态/帮助信息 |
| `Diagnostics` | 跟踪误差、每段 RMSE、电流和控制时序指标 |
| `Telemetry` | 固定21列、约20 Hz CSV，非阻塞发送队列 |
| `Config.h` | 项目使用的固定参数与配置 |
| `Runtime.h` | 当前工程的共享状态声明，用于跨模块访问同一份运行数据 |

## 主循环顺序

1. 记录循环起点。
2. 执行 FOC 更新、轨迹求值、闭环运动指令及诊断。
3. 解析串口命令并维护自动往返运动。
4. 按周期准备 CSV；分批清空串口发送缓冲区。
5. 记录本次循环耗时，处理延迟生效的诊断复位。

当前主循环没有额外拆成多个 FreeRTOS 任务。在线 N 求解在接收到命令时同步执行；与之相关的耗时可以通过 `S/I` 诊断查看。

## 在线重规划

收到 `N<absolute_target>` 时，以**当前规划状态**（位置、速度、加速度）为起点计算新轨迹。如果新目标过近、现有速度无法直接安全制动到目标，可先按限制制动并越程，再从静止点返回新目标。若规划约束不满足，命令可能被拒绝，原轨迹继续执行。

这不是一个声称全局时间最优的在线规划器。算法的数值约束需要与真实电机速度、加速度测量分开理解。
